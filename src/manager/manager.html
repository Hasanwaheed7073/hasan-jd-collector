JD Collector

Collection

How hard the collector drives LinkedIn. Slower is safer: at 1.2s per job a 25-job page takes about 40 seconds.

A run also stops on its own after two pages that add no new jobs — that is what keeps a surface like the AI job search, which ignores page offsets, from reloading the same list until the page limit runs out.

Prompt & export

Prepended to every batch you copy or download. The extension adds the postings and their parsed facts below it and nothing else — it states no opinion about any job, so whatever you want the model to weigh belongs here.

A single posting longer than the batch budget still gets its own batch rather than being dropped.

This asks the chat you paste batches into to end its reply with one machine-readable line per job, so Vetting feedback can read those calls back in. It changes the shape of the reply, never its content — nothing here tells the model what to conclude.

Vetting feedback

Reads accept/reject calls back out of the chat you paste batches into, so a job you already turned down does not come back on the next run. The extension forms no opinion of its own — the call was yours, this only remembers it. Open the chat in a tab, then scan.

AI assist

    

      LinkedIn's AI job search has no selectors worth writing: its class names
      are build hashes that rotate on every deploy. When the built-in
      structure-based fallbacks come up empty, this describes the page to a
      model and asks it where things are — the list, a card, the
      title, the description — then checks every selector it gets back
      against the real page before using any of them.
    

    

      It is never asked what a job says or whether a job is any good. Facts
      still come out of the page, through the same parsers as always.

        Field check
      

      
      

        This one sends posting text. Up to 4,000 characters of the
        job's own pane — the header plus the start of the description —
        goes to the model for each job with a missing field. The selector assist
        above never sends that; this does. It also costs one call per job, which
        on a free endpoint is the difference between a run and an afternoon, so
        it is capped.
      

      

        What it may return: only values that appear in the text it
        was shown, checked character for character before anything is kept. A
        company name that is not on the page is discarded; a salary that is not on
        the page is discarded. It fills gaps only — a field the page already
        yielded is never overwritten — and every field it did fill is labelled
        as such on the row and in the export. It is never asked whether a job is
        any good, and there is still no score, rank or fit anywhere in here.
      

      
      

        
        
      


      

        
        
        
        
      

      


      

        Remembered page plans
        

          
          
        

      

      


      

        What is sent: a structural outline of the page — tags,
        ids, class names, a few attributes, and visible label text truncated to
        60 characters, with hidden elements dropped and repeated cards collapsed.
        Job descriptions are not included, and nothing is sent unless a page has
        already defeated the built-in selectors. A resolved page is remembered,
        so later runs on the same surface cost no calls at all.
      

      

        A selector is used only if it matches the right number of elements with
        the right shape of content, and never if the hand-written selector for
        that field still works — so this can fill a gap but can never take
        over a layout that already collects.
      

    

  


  
  

    
Diagnostics

    

      When a page collects nothing — a LinkedIn redesign, the AI job search, a
      new board — this reports structure only: tags, classes and counts. No
      job text, no personal data. That output is what a precise adapter gets
      written from.
    


    

      

        
        
        
        
        
      

      

      

        Trace one AI-search job runs the whole pipeline against a
        single job on the open tab — card discovered, clicked, selection
        synchronised, extracted, validated, payload built, saved — and prints
        what each stage saw, including field lengths and the save response. Prove
        a surface on one job before turning a run loose on four hundred. The job
        it traces is collected for real, so it will appear in Results.
